# S-02 · Hook enforcement and delegation — findings

**Outcome: A2 and A3 confirmed on Copilot Free. D-08 keeps runtime-native `customAgents` for delegation; the per-agent model half moves to S-03, and on Free the override is not honored.** With the pinned SDK (`@github/copilot-sdk` 1.0.28, bundled CLI 1.0.105) and the default model (`auto`):

- `onPreToolUse` fires for the main agent's and the sub-agent's tool calls. **The distinguishing field is `agentId`**: absent on main-agent calls, a UUID on sub-agent calls. Sub-agent calls also carry `agentType` (the custom agent's `name`, here `bulk-reader`) and `parentAgentId` (the parent session ID).
- A deny with a reason that names `bulk-reader` makes the main agent delegate. **20 of 20 trials** (19 needed) ended with `bulk-reader` reading the 219 KB fixture and no fixture line reaching the main agent. Every trial took exactly one deny (the main agent's first `view`), then one `task` call, and every final answer was correct. A trial took 6–14 s and about 0.32 AIU.

## What was built

`spikes/s-02-hooks/s02.mjs` (throwaway). Like S-01, it imports the SDK from the adapter's `node_modules` and redacts the login, temporary directories, the home directory and anything shaped like a GitHub token from saved output.

- `tools` calls `client.rpc.tools.list({})` (no prompt) and saves every built-in tool's name and JSON Schema to [`S-02-tools.json`](S-02-tools.json), grouped under `read`, `write`, `edit`, `search` and `shell`. `check-tools` asserts the file offline.
- Each trial writes a fresh temporary directory holding `services-registry.txt`: 2,300 service records, about 219 KB (about 224,300 bytes), with one record for `kestrel-ledger-prod-77` at a random line and a random `retention_days`. It opens a session with no model, one custom agent and two hooks, and sends: *"In services-registry.txt in the current directory, what is the retention_days value for kestrel-ledger-prod-77? Reply with just the number."*
  - `bulk-reader`: `tools: ["view", "grep", "glob"]`, `infer: true`, a prompt telling it to answer in at most three sentences and never paste file contents.
  - `onPreToolUse` treats a call with no `agentId` as the main agent's. It denies a main-agent `view` of any file over 32 KB, a main-agent `grep`/`rg` that targets the fixture or a directory, and a main-agent `bash` whose command names the fixture. The reason says the file's size and the limit and tells the agent to delegate to `bulk-reader` with the `task` tool. Everything else is allowed.
  - `onPostToolUse` records the result size per agent.
  - The permission handler approves `read` requests. None were raised: reads inside the working directory need no permission.
- `probe` runs one trial and saves the hook payloads and events to [`S-02-probe.json`](S-02-probe.json) (the saved one is from the `make verify` run; an earlier exploratory probe is quoted below where it differed) (`model.*`, `hook.*` and `session.usage_info` events dropped). `PROBE_MODEL=<id>` sets `bulk-reader`'s `model`; the run with `claude-haiku-4.5` is [`S-02-probe-model.json`](S-02-probe-model.json).
- `trials N` runs N trials and saves a per-trial summary to [`S-02-trials.json`](S-02-trials.json). A trial passes when the session reaches idle, a `subagent.started` fires, a sub-agent `view`/`grep`/`rg` of the fixture is allowed, and no main-agent `tool.execution_complete` result contains any of 24 sampled fixture lines (every line but the answer line is eligible, so a `task` result that pastes neighbouring lines fails). It stops early on a send error or a quota or rate-limit error.

## Hook payloads

Main agent (`view` of the fixture, denied):

```json
{ "sessionId": "<parent>", "timestamp": "…", "toolName": "view",
  "toolArgs": { "path": "<workdir>/services-registry.txt" }, "workingDirectory": "<workdir>" }
```

Sub-agent (`view` of the same file, allowed):

```json
{ "sessionId": "<child>", "timestamp": "…", "toolName": "view",
  "toolArgs": { "path": "<workdir>/services-registry.txt" },
  "agentId": "<child>", "agentType": "bulk-reader", "parentAgentId": "<parent>", "workingDirectory": "<workdir>" }
```

- On sub-agent calls `input.sessionId` is the child session ID and equals `agentId`; `invocation.sessionId` (the callback's second argument) is still the parent session. On main-agent calls both are the parent.
- `agentId` equals the `agentId` on the `subagent.started` event's envelope and on every event the sub-agent emits. `subagent.started.data.toolCallId` is the main agent's `task` call ID, and the sub-agent's `tool.execution_start` events carry it as `parentToolCallId` (deprecated field).
- `onPostToolUse` gets the same identity fields plus `toolResult`.
- The keys are the same in every trial. The only main-agent call that ever needed denying was `view`.

## Delegation

The main agent tries `view` on the file, gets the deny, and calls `task` with `agent_type: "bulk-reader"`, `mode: "sync"`, a `name`, a `description` and a self-contained `prompt` ("Open services-registry.txt … return only the numeric value …"). `bulk-reader` runs, answers, and the `task` result (a few dozen characters) is all the main agent sees.

How `bulk-reader` reads depends on the model `auto` routes it to:

- On `mai-code-1.1-flash` (saved probe, 17 trials) it views a range first in 15 trials (`view_range: [1, 250]` in 13, `[1, 400]` and `[1, -1]` once each) and unranged in 2, then searches with `grep`. `grep` got `path` (singular, not in the `tools.list` schema) in 8 trials and `paths` in 9.
- On `gpt-6-luna` (first exploratory probe, 3 trials) it views unranged or skips straight to search, and the search tool is `rg`, always with `paths`.

The runtime has **its own large-file guard**: the unranged `view` of the 219 KB file returned *"File too large to read at once (219.0 KB). Consider using the grep tool …"* instead of the content. `view` takes `forceReadLargeFiles: true` to override it, and its schema says files over 20 KB are otherwise truncated. Neither agent ever had the whole file in context.

## `auto` and the sub-agent model

- With no `model` on the agent, `subagent.started` reports `modelSelectionSource: "session_inheritance"` and the session's current routed model (`mai-code-1.1-flash` in all trials). `auto` then routes each sub-agent call on its own: in the first exploratory probe and in 3 of 20 trials the sub-agent ran on `gpt-6-luna` instead. In the exploratory probe `subagent.completed` reported `firstDispatchedModel: "gpt-6-luna"` but `model: "mai-code-1.1-flash"`.
- With `model: "claude-haiku-4.5"` (`modelPolicy` default `preferred`), `subagent.started.model` and `subagent.configured.model` say `claude-haiku-4.5` with `modelSelectionSource: "agent_definition_default"`, but **every sub-agent `assistant.usage.model` is `mai-code-1.1-flash`**, the model `auto` gave the parent. There is no error, warning or `fallback: true`. **For S-03:** on Free the override is silently not honored, so `subagent.started.model` is not evidence of the model used; only `assistant.usage.model` is. S-03's first check cannot pass on Free; it needs a plan that lists concrete models, or should be reworded to "when the plan lists the worker model". `modelPolicy: "required"` was not tried.
- Each sub-agent `assistant.usage` carries the sub-agent's `agentId`, so per-agent attribution (A5) looks direct. S-03 should confirm it.

## Built-in tools

`tools.list` returns 16 built-in tools: `bash read_bash stop_bash list_bash glob grep create edit skill view web_fetch task read_agent list_agents write_agent` (plus none from MCP in this session). Argument shapes are in [`S-02-tools.json`](S-02-tools.json). The ones Pica's policy reads:

| Capability | Tool | Arguments (required in bold) |
|---|---|---|
| read | `view` | **`path`** (absolute), `view_range: [start, end]` (1-based, inclusive, `-1` = EOF), `forceReadLargeFiles` |
| write | `create` | **`path`**, **`file_text`** |
| edit | `edit` | **`path`**, `old_str`, `new_str` |
| search | `grep` (reported as `rg` in hooks and events when `auto` routes to `gpt-6-luna`), `glob` | grep: **`pattern`**, `paths` (directory string or array, default cwd), `glob`, `type`, `output_mode`, `-A`/`-B`/`-C`/`-i`/`-n`, `head_limit`, `multiline`; glob: **`pattern`**, `paths` |
| shell | `bash` | **`command`**, **`description`**, `mode`, `initial_wait`, `detach`, `shellId` |
| delegate | `task` | **`name`**, **`prompt`**, **`agent_type`**, **`description`**, `mode` (`sync`/`background`), `model`, `reasoning_effort`, `context_tier` |

`tools.list` takes an optional `model`; without one it lists `grep`. The name a model actually calls varies by routed model (mismatch 1).

## Mismatches with C-02 and C-04

Items 1 to 4 and 6 to 8 were fixed after the spike. Each item says what changed, then what the spike found. Item 5 needed no code change.

1. **Fixed: the search tool's name depends on the routed model.** `rg` is in the catalog, and the read gate reads `path` and `paths`, as a string or an array, for both `grep` and `rg`. What the spike found: (`core/src/agents/tool-catalog.ts`). `tools.list` (no model) and the custom agent's `tools` say `grep`. In hooks and `tool.execution_*` events the sub-agent's search was `grep` when `auto` routed it to `mai-code-1.1-flash` (17 trials) and `rg` when it routed to `gpt-6-luna` (the first exploratory probe and 3 trials), and the arguments vary too: `grep` got `path` (singular, not in the `tools.list` schema) about half the time and `paths` otherwise; `rg` always got `paths`. `toolKind("rg")` is `undefined`, so rules that key on kind miss those searches. The catalog needs per-model aliases (`rg` → search at least), ideally built from `tools.list({ model })` for each model `auto` may route to; other tools may be renamed the same way. Argument readers (C-04's path extraction, R-07/S-04 scope checks) must accept both `path` and `paths`.
2. **Fixed: catalog contents.** `builtinTools` (formerly `provisionalBuiltinTools`) now lists the 16 tools below plus `rg` and `apply_patch`, so `toolKind("rg")` is `search` (part of item 1). What the spike found: The runtime has no `write_bash` and no `update_todo`. It adds `skill`, `read_agent`, `list_agents` and `write_agent` (background sub-agent control, kind `agent`). Swap the array for `S-02-tools.json` as C-02's hand-over says.
3. **Fixed: C-04 gated only `view`.** The read gate now also judges content searches (`grep` with `output_mode: "content"`, and `rg` by default) and whole-file prints in shell commands (`cat`, `less`, `more`). What the spike found: (`core/src/sessions/pre-tool-use.ts`, `core/src/policy/cost.ts` `largeReadRule`). A main-agent `grep`/`rg` over a large file returns its matching lines, and `bash cat` returns all of it; neither goes through the large-read rule. The spike denied both, though in 22 runs the main agent never tried them. The oversized-output rule (C-06) caps the damage but does not keep content out of the main agent.
4. **Fixed: C-04's range exemption vs. `view`'s own limit.** `forceReadLargeFiles: true` is never range-exempt, and `bulk-reader`'s prompt tells it to read ranges or search. What the spike found: `largeReadRule` allows a ranged read up to `rangeExemptLines`, and the runtime separately truncates or refuses unranged reads over about 20 KB unless `forceReadLargeFiles` is set. The gate should deny `forceReadLargeFiles: true` from the main agent regardless of range, and `bulk-reader`'s prompt should tell it to use `view_range` or search, since its own unranged `view` is refused.
5. **`view.path` is absolute** in practice (the model always passed an absolute path). C-04's `fileSize` port resolves relative paths; that still works, but tests should use absolute paths to match the runtime.
6. **Fixed: agent identity.** Hooks pass `agentType` and `parentAgentId` through, and policy names a sub-agent by its `agentType`. A call without `agentId` is still the main agent's. What the spike found:: `agent = input.agentId ?? "main"` matches the runtime, and `adapters/src/copilot/hooks.ts` passes `agentId` through. It drops `agentType` and `parentAgentId`, which the policy and the timeline would want ("redirected to bulk-reader").
7. **Fixed: `subagent.*` agent id.** It now comes from the event envelope, with the `task` call id used only when the envelope has none. What the spike found: The real sub-agent ID is the event envelope's `agentId` (a UUID), which is what hooks and every other sub-agent event carry. With the current mapping, `subagent.started.agentId` never equals the `agentId` on that sub-agent's own tool and usage events. Map it from the envelope and keep `toolCallId` as its own field.
8. **Fixed: denied calls in the timeline.** The adapter reports a call its pre hook denied as failed, with `Denied by Pica policy: <reason>`. What the spike found: and a `tool.execution_complete` with `result: null`. The timeline should show it as denied by policy, not as a tool that ran and returned nothing.

## Quota

Free reports `chat` 200 / `completions` 2000 request counts, all `tokenBasedBilling: true`. Across the probes and trials neither `usedRequests` count moved (`chat` stayed at 0 used, 99.8 % remaining), so these snapshots do not track this usage; the real cost is in `assistant.usage.copilotUsage.totalNanoAiu` (S-01). A trial cost 0.17–0.49 AIU (mean 0.32), so the 20-trial run cost about 6.4 AIU. No call was refused.

## Reproduce

```sh
PICA_LIVE=1 make verify UNIT=S-02    # probe + 20 trials + tool file check + A2/A3/D-08 check
node spikes/s-02-hooks/s02.mjs tools  # re-record S-02-tools.json (no prompt)
PROBE_MODEL=claude-haiku-4.5 node spikes/s-02-hooks/s02.mjs probe
```

The live checks need a Copilot CLI login (`copilot login`) and are skipped without `PICA_LIVE=1`. They never run in CI.
