# S-03 · Per-agent model and attribution — findings

**Outcome: A5 confirmed and A4 not confirmed, both on Copilot Free. Free is a default-model-only plan, so A4's fallback is the decision for such plans. A plan that lists models has not been tested.** Results with the pinned SDK (`@github/copilot-sdk` 1.0.28, bundled CLI 1.0.105) and `models.list` = `[auto]`:

- **Model (check 1, A4).** A `bulk-reader` with `model: "claude-haiku-4.5"` reports that model in `subagent.started`, `subagent.configured` and `subagent.completed`, but every sub-agent `assistant.usage.model` is the model `auto` picked (`mai-code-1.1-flash` in one run and `gpt-6-luna` in two). `modelPolicy: "required"` changes `modelSelectionSource` to `configured_required` and is otherwise ignored the same way. Neither case gives an error or a warning.
- **Attribution (check 2, A5).** Each `assistant.usage` belongs to exactly one agent through its **envelope `agentId`**: no id means the main agent, and a sub-agent's id equals the envelope `agentId` on its `subagent.started`. `getMetrics.agentMetrics` is keyed the same way (`main`, then the sub-agent's id, with `agentName`), and the per-agent sums match it to the nano-AIU. Pica's adapter mapping and normalizer, run over the recorded events, name the right agent for every call.
- **Budget (check 3).** Free cannot set a low `maxAiCredits`: `session.create` refuses any value below 30 with *"Minimum session limit is 30 AI credits."* A delegating trial costs about 0.1 to 0.5 credits, so the runtime cap never fires in a test. C-09's `SessionBudget`, fed from each `assistant.usage`, was crossed by a sub-agent call, and an abort stopped the session there. No model call was billed after the abort, and the main agent never answered. The abort is spike code: the shipped engine only warns (mismatch 2).
- **Credits (check 4).** Free lists no token prices, so credits are Σ `assistant.usage.copilotUsage.totalNanoAiu` / 10⁹. That sum matches `getMetrics.totalNanoAiu` exactly (0.000 % apart) in every run. The shipped ledger records **0** for these calls (mismatch 1).

## Check 1 · per-agent model

The saved run is from the `make verify UNIT=S-03` run:

| | Configured | `subagent.started.model` (`modelSelectionSource`) | `subagent.completed` | Sub-agent `assistant.usage.model` |
|---|---|---|---|---|
| Exploratory run, `preferred` (default) | `claude-haiku-4.5` | `claude-haiku-4.5` (`agent_definition_default`) | `model: claude-haiku-4.5`, `firstDispatchedModel: mai-code-1.1-flash` | `mai-code-1.1-flash` × 3 |
| `required` | `claude-haiku-4.5` | `claude-haiku-4.5` (`configured_required`) | `model: claude-haiku-4.5`, `firstDispatchedModel: gpt-6-luna` | `gpt-6-luna` × 2 |
| Saved run, `preferred` | `claude-haiku-4.5` | `claude-haiku-4.5` (`agent_definition_default`) | `model: claude-haiku-4.5`, `firstDispatchedModel: gpt-6-luna` | `gpt-6-luna` × 2 |

In every run the sub-agent ran on the same model `auto` gave the main agent. All usage events have `isAuto: true`. **`subagent.*.model` reports the requested model, not the one used.** On `subagent.completed`, `firstDispatchedModel` is the honest field, and `assistant.usage.model` is the authoritative one.

The SDK documents `model` as "falling back to the parent session model if unavailable unless `modelPolicy` is `required`". On Free, `required` does not fail, so even a hard requirement cannot detect a plan that ignores the override. Pica has to compare the billed model with the requested one itself.

**Decision for default-model-only plans (A4's fallback).** Pica does not rely on the `customAgents` `model`. Engine-managed child sessions with an explicit model gain nothing on these plans, because the only model is `auto`. So the worker gets no model there, and Pica shows the model that `assistant.usage` reports. On such plans the router saves by keeping large content out of the main agent's context, not by using a cheaper model. Whether a plan that lists models honors the override is untested. Re-run `PICA_LIVE=1 make verify UNIT=S-03` on one: check 1 then asserts equality, and if the override is still ignored, the `Delegator` uses engine-managed child sessions with an explicit model there (D-08).

## Mismatches with C-08, C-09 and the normalizer

Every item was fixed after the spike, and each says what changed.

1. **Fixed: the ledger recorded 0 credits on Free (C-08).** `assistant.usage` now carries `billedCredits`, taken from `copilotUsage.totalNanoAiu` / 10⁹. The normalizer puts it on `usage.recorded`, and the ledger keeps a billed amount and prices only unbilled calls. The `inputTokens` point below is still open. What the spike found: `withUsageLedger` prices `usage.recorded` from `pricesFor(model)`. Free has no prices, so it reports `usage.price_unknown` and keeps the normalizer's `credits: 0`. Every rollup, savings estimate and budget on Free therefore reads 0. The runtime port's `assistant.usage` (`core/src/runtime/events.ts`) carries no cost, and the adapter (`adapters/src/copilot/events.ts`) drops `copilotUsage`. The fix is to carry `copilotUsage.totalNanoAiu` (and `aiCreditsStatus`) through the port, and to have the ledger prefer it over computed prices: it is the billed amount on every plan, and the only one on Free. S-01 mismatch 2 also still holds: `inputTokens` includes cache reads (main call 2: 12,505 input, of which 12,393 were cache reads), and the adapter keeps it as uncached input.
2. **Fixed: C-09's budget only warned, and limits under 30 failed.** The runtime port has `minSessionCredits`, which is 30 for Copilot. A limit below it is not passed as `maxAiCredits`. The engine enforces it instead: it aborts the turn with reason `budget` once spend reaches the limit, and refuses later turns with `session.budget_exhausted`. A limit at or above the floor still goes to the runtime and its approval flow. When an engine-enforced limit runs out, the engine raises the same budget approval (`budget.exhausted`) as the runtime path. Allowing it with `budgetCredits` raises the limit. The approval is raised again on resume. What the spike found: Enforcement is left to the runtime's `maxAiCredits`. The engine's `SessionBudget` emits `budget.warning` and never blocks or aborts. On Free this has three effects:
   - `budget.sessionCredits` (or a managed ceiling) below 30 makes `session.create` fail outright, because the adapter passes it unchanged.
   - At 30 or more, the cap is untested.
   - With mismatch 1, the engine budget sees 0 spend.

   The engine needs its own stop: when spend reaches the limit, abort the turn (or hold the next call) and raise the existing budget approval. The runtime should get `maxAiCredits` only when the limit is at least the floor. The spike's abort shows this works mid-sub-agent and stops billing at once.
3. **Fixed: the `subagent.*` model was the requested one, not the one used.** `subagent.completed.model` is now the model it ran on (`firstDispatchedModel`), with `requestedModel` set when the two differ. `subagent.started` still carries the requested model. What the spike found: the `subagent.*` model is the requested model, not the used one (`core/src/events/normalize.ts`, adapter `subagent.*` mapping).** Pica's `subagent.started` and `subagent.completed` carry `model: "claude-haiku-4.5"`, and the timeline would show that, while every call ran on `auto`'s pick. Use `subagent.completed.firstDispatchedModel` or the sub-agent's `assistant.usage.model`. Keep `modelSelectionSource` so the timeline can say the override was not applied.
4. **Fixed: an aborted sub-agent reported `subagent.completed`.** On `abort`, the open tool calls and sub-agents are closed as `tool.failed` and `subagent.failed` ("Interrupted: the turn was aborted"). The runtime's later `subagent.completed` or `tool.execution_complete` for them is dropped. What the spike found: an aborted sub-agent reports `subagent.completed` (`normalize.ts`).** After `session.abort()`, the runtime emits `subagent.completed`, not `subagent.failed`, and a `tool.execution_start` with no `tool.execution_complete`. Pica would show a finished delegation and leave a tool open in `NormalizerState.tools`. It should treat a `subagent.completed` after `abort` (or alongside `agent.interrupted`) as interrupted, and close open tools on `abort`.
5. **Fixed: the ledger agent key is the agent's name.** `usage.recorded` now also carries `agentInstanceId`, the runtime id. Rollups still group by name. What the spike found: the ledger agent key is the agent's name. The normalizer resolves the envelope `agentId` to the name (`bulk-reader`), so two concurrent `bulk-reader` instances share one ledger key. That is fine for per-definition rollups. The instance id should stay available (it is the `getMetrics.agentMetrics` key) for the timeline and for reconciling against `getMetrics`.
6. **Fixed: unmodelled fields.** `usage.recorded` carries `initiator` and `premiumRequests` (from `cost`). `parentToolCallId` is not added, because the normalizer already derives the parent call from the agent id. What the spike found: `assistant.usage.initiator` (`user`, `agent`, `sub-agent`) and `parentToolCallId` cross-check attribution. The premium-request `cost` is 1 on the main agent's first call and 0 on sub-agent calls (`agentMetrics[…].requests.cost`).

## Quota

Six prompts in all: two exploratory attribution runs (the first crashed in the spike's own analysis after the prompt completed, which is why raw events are now saved first), one `required` run, one exploratory `limit` run, and the `make verify UNIT=S-03` run's attribution and limit trials. Recorded runs cost 0.09 to 0.51 credits each, about 1 credit in total plus the crashed run. No call was refused for quota or rate. The only refusals were the deliberate `maxAiCredits` floor probes, which send no prompt.

## Reproduce

```sh
PICA_LIVE=1 make verify UNIT=S-03                 # 2 prompts: attribution, then agents/credits from its file, then limit; A4/A5 check
node --experimental-strip-types --disable-warning=ExperimentalWarning spikes/s-03-attribution/s03.mjs probe-limit   # no prompt
MODEL_POLICY=required node --experimental-strip-types --disable-warning=ExperimentalWarning spikes/s-03-attribution/s03.mjs attribution
```

The live checks need a Copilot CLI login (`copilot login`) and are skipped without `PICA_LIVE=1`. They never run in CI. On a plan that lists models, set `WORKER_MODEL` to one it lists: check 1 then asserts the started and billed models equal it. Check 4 still compares the reported cost. Pricing from `tokenPrices` waits on the ledger fix (mismatch 1).
