# S-01 · Runtime access and auth — findings

**Outcome: A1 confirmed for Copilot Free. Business is untested.** The pinned SDK (`@github/copilot-sdk` 1.0.28, bundled CLI 1.0.105) signs in as the local user, creates a session and completes a prompt on Copilot Free. Free is a **default-model-only plan**. `models.list` returns only the virtual `auto` model, with no capabilities and no prices. A prompt that names no model runs on `auto`, which routes each call to a concrete model (`gpt-6-luna` on the first run, `mai-code-1.1-flash` on the second) at `medium` reasoning effort. The `assistant.usage` event reports tokens and a cost in nano-AIU. The owner's environment, Copilot Business, could not be tested: the Business account cannot be signed in from the development Mac. D-16 is extended with what a default-model-only plan means for Pica.

## What was built

`spikes/s-01-runtime/s01.mjs` (throwaway). It imports the SDK from the adapter's own `node_modules`, so it runs the exact pinned version.

- `models` — checks auth, then calls `models.list` raw (the SDK's `listModels()` drops `auto` and `imageModels`), `models.listTokenPriceUnits` and `account.getQuota`. It also opens one session with no model and reads `session.model.list` and `session.model.getCurrent`, which sends no prompt. Everything is saved to [`S-01-models.json`](S-01-models.json). The check passes when a model is listed or the session has a default. Token prices are reported, not required (D-16).
- `prompt` — sends `Reply with the single word: ok` to the cheapest priced model, or, when no model is priced, to the session default with no explicit model and no effort override (the plan's standard setting). It denies every permission request and runs in a temporary directory. The full event log, `session.model.getCurrent` before and after, and `usage.getMetrics` go to [`S-01-events.json`](S-01-events.json). It asserts `session.idle` within 120 s and at least one `assistant.usage`.

Both files are redacted: the login, home directory and temporary directory are replaced, and strings over 400 characters (system prompt, message snapshots) are cut.

## Auth

1. **First run:** no Copilot CLI login was stored (`~/.copilot/config.json` held only `firstLaunchAt`). The runtime silently fell back to the `gh` CLI token (`authType: "gh-cli"`). That account is on Free (`access_type_sku: "free_limited_copilot"`, `copilot_plan: "individual"`, no organizations). `models.list` returned `{ "models": [] }`, an empty list, not even `auto`.
2. **After the owner signed in to the Copilot CLI** with the same Free account (`authType: "user"`), `models.list` returned `auto`. Every result below is from this sign-in.

So the credential source changes the model list for the same account: through the `gh` token, Free exposes nothing usable. `getAuthStatus().authType` says which source is active, and Pica should show it (see the mismatches below).

`account.getAllUsers` returns each account's raw OAuth token in `token`. Pica must never log that result.

## What the runtime returns on Free

| Call | Result |
|---|---|
| `models.list` | `models: [{ id: "auto", name: "Auto", capabilities: {} }]`. No `billing`, no `policy`, no `auto` tier metadata. One `imageModels` entry, `availability: "unavailable"` |
| `models.listTokenPriceUnits` | `{ units: [] }` |
| `session.model.list` | The same `auto` entry plus a provider roster (`copilot`), and `modelPriceCategories` listing 15 catalog models that `auto` may pick (for example `claude-haiku-4.5`, `gpt-6-luna`, `gpt-5.6-luna-free-auto`), each tagged `low`/`medium`/`high`. These are categories, not prices |
| `session.model.getCurrent` | `{}` before the first prompt; `{ modelId: "auto" }` after it |
| `account.getQuota` | Snapshots `chat` (200), `completions` (2000) and `premium_interactions` (entitlement 0, `hasQuota: false`), all `tokenBasedBilling: true`, all request counts. No `ai_credits` key |

### "Copilot Fusion" and effort levels

The SDK has the names but this account never advertises them:

- `ManagedFusionTier` = `standard` (Auto Balance) | `high` (HydraFusion) | `max` (HydraFusion Max) | `unmanaged`. It matches the owner's "standard, high, max". It is an **administrator managed setting** (`fusionTier` in managed settings), not a per-session option. Here `session.managed_settings_resolved` reported `source: "none"`, with no managed keys.
- The per-session knob is `autoTier` (`efficiency` | `balance` | `intelligence` | `fast`), set with `session.model.switchAutoTier`. It applies only on the next prompt to `auto`. The tiers a plan offers come from `models.list`'s `auto` field (`AutoTierMetadata`: `defaultTier` plus descriptors with `type` `auto` or `fusion` and an optional `fusionTier`). **Free returned no `auto` metadata**, so no tier can be listed. `switchAutoTier` was not tried, since it only acts on a later prompt and the spike sends one.
- `reasoningEffort` (`low`…`max`) also exists, but `auto` declares no `capabilities.supports.reasoningEffort`. The prompt ran at the runtime's `medium`.

The prompt ran with `autoTier: null` (provider default) and no effort set, which is the "standard" path. Neither the word Fusion nor a `fusion` attribution appeared in any event.

### The prompt

Two prompts were sent: the exploratory run and the `make verify UNIT=S-01` run. [`S-01-events.json`](S-01-events.json) holds the second. Events, in order (38 in both runs): `session.start` → `session.model_change` (`newModel: "auto"`, `source: "startup"`) → `session.auto_mode_resolved` (`chosenModel: "gpt-6-luna"`, `availableModels: ["gpt-6-luna"]`, `routingMethod: "auto_v2"`) → … → `assistant.usage` → `assistant.message` (`"ok"`) → `assistant.turn_end` → `session.usage_checkpoint` → `assistant.idle` → `session.idle` → `session.shutdown`. There was no `session.error`.

`assistant.usage`:

| Field | Run 1 (`gpt-6-luna`) | Run 2 (`mai-code-1.1-flash`, saved) |
|---|---|---|
| `model` | the routed model, not `auto`; `isAuto: true` | same |
| `inputTokens` | 12,330 = 3 uncached + 12,327 cache write | 11,297 = 10,017 uncached + 1,280 cache read |
| `cacheWriteTokens` / `cacheReadTokens` | 12,327 / 0 | 0 / 1,280 |
| `outputTokens` / `reasoningTokens` | 5 / 0 | 5 / 0 |
| `reasoningEffort` | `medium` | `medium` |
| `cost` | 1 (premium-request multiplier) | 1 |
| `copilotUsage.tokenDetails` `costPerBatch` (nano-AIU per 1,000,000 tokens) | input 1e10, cache read 1e9, cache write 1.25e10, output 5e10 | input 2e10, cache read 2e9, cache write 2.5e10, output 1.2e11 |
| `copilotUsage.totalNanoAiu` | 154,367,500 (≈ 0.154 AIU) | 203,500,000 (≈ 0.204 AIU) |
| `aiCreditsStatus` | `complete` | `complete` |

In both runs `totalNanoAiu` equals Σ `tokenCount × costPerBatch / batchSize` over the token details exactly. Free gets real per-token prices after the fact, even though `models.list` publishes none. `auto` routing is not stable across identical prompts.

`usage.getMetrics` and `session.shutdown.accountingSnapshot` carry the same total per model and per agent (`agentMetrics.main`). Of the context window, `session.usage_info` attributed 7,713 tokens to tool definitions and 5,875 to the system prompt.

## Which fields are plan-dependent (D-16)

| Field | Free (tested) | Business (expected, untested) |
|---|---|---|
| `models.list` entries | `auto` only | Concrete models allowed by org policy, plus `auto` |
| `billing.tokenPrices`, `listTokenPriceUnits` | absent / empty | present per model |
| `billing.multiplier`, `policy.state` | absent | present |
| `capabilities` (limits, `reasoningEffort` support) | `{}` | per model |
| `models.list.auto` tier metadata | absent | possibly present, if the org enables tiers or Fusion |
| Managed `fusionTier` | none | admin-set |
| Quota snapshot keys | `chat`, `completions`, `premium_interactions` | likely different, with credits pooled per org (§2.1) |
| `assistant.usage` token details, `totalNanoAiu` | present | expected present |
| `gh` token fallback | Empty model list | Unknown |

Prices on Free are therefore only visible **after** a call, in `assistant.usage.copilotUsage`, never ahead of one from `models.list`.

## Adapter mismatches (`engine/packages/adapters/src/copilot/`)

Recorded for follow-up units. All seven are now fixed.

1. **Fixed: `models.ts` price units.** `listModels` reads each model's unit from `models.listTokenPriceUnits` and divides nano-AIU prices by 10^9. A price with no reported unit, or every price when that call fails, is dropped, so the model shows "not available on this plan" and the fallback table may fill it in. What the spike found: `toRuntimeModel` assumes `tokenPrices` are in AI Credits. The SDK reports each model's unit through `listTokenPriceUnits` as "AI Credits or nano-AIU", and usage costs come in nano-AIU. The adapter must read the unit and convert. It must also not treat a model with no prices as free: a missing price needs to stay "not available on this plan".
2. **Fixed: `events.ts` / `usage.ts` token split.** The adapter now subtracts `cacheReadTokens` from `inputTokens`, so cache reads are counted once, as cached input. Cache writes stay in `inputTokens`, because the port has no rate for them. Cost itself comes from `totalNanoAiu` since S-03's fix. What the spike found: `inputTokens` includes both cache writes (run 1: 12,330 = 3 + 12,327) and cache reads (run 2: 11,297 = 10,017 + 1,280). The adapter maps `cachedInputTokens` from `cacheReadTokens`, drops `cacheWriteTokens`, and keeps `inputTokens` as uncached input. Pricing from that bills cached tokens at the full input rate (cache reads cost a tenth of it). The authoritative cost is `copilotUsage.totalNanoAiu`, with per-type counts in `copilotUsage.tokenDetails`. C-08 should record those instead.
3. **Fixed: the `session.start` model was always empty.** The port has a `session.model_change` event, mapped from `newModel`, and `session.start.model` is documented as empty until that event arrives. What the spike found: The adapter reads `data.selectedModel`, which the real event does not carry, so the port's `session.start.model` is always `""`. The selected model arrives in `session.model_change.newModel` (`auto`), and the routed model in `session.auto_mode_resolved.chosenModel` and on each `assistant.usage.model`.
4. **Fixed: `models.ts` `toQuotaInfo`.** Only the `ai_credits` snapshot is read as a credit quota. Without one, `quota()` returns `null`, meaning the plan reports no AI-credit quota (D-16), instead of 0 of 0. What the spike found: It prefers `ai_credits`, then `premium_interactions`. Free has no `ai_credits`, and `premium_interactions` has entitlement 0, so Pica would report 0 of 0 credits, which reads as "exhausted", on a plan that works. All the snapshots are request counts, not credits.
5. **Fixed: `copilot-runtime.ts` auth.** `connect()` now also lists models, bypassing the SDK's model cache; an empty list fails with the new `runtime.no_models` (client code `auth_required`), whose message names the login, the credential source and `copilot login`. The optional port method `account()` returns `login`, `authType` and `host`, and clients read it through `engine.account` (status `signed_in`, `signed_out`, `no_models` or `unknown`, plus the message). **Checked live 2026-11-15:** with an empty `COPILOT_HOME` the runtime falls back to the `gh` token, and `listModels` fails with `runtime.no_models`, naming `gh-cli` and `copilot login` (`live-smoke.test.ts`, run with `PICA_LIVE=1`). What the spike found: `connect()` checks only `isAuthenticated`. It accepted the `gh` fallback account, which has no usable models. The adapter should surface `authType` and `login`, and treat "authenticated but `models.list` empty" as its own state with a sign-in hint (`copilot login`).
6. **Fixed (no code change needed): model choice on default-only plans.** Tier resolution already resolves every tier to `null` (`unresolved`, so no model is passed and the runtime routes) when the only listed model is the unpriced `auto`; `core/tests/models/tiers.test.ts` now pins this. Per-agent `model` overrides still cannot work on Free (S-03, D-08). What the spike found: `checkModel` rejects any model not in `models.list`, so on Free only `auto` (or no model) works. Tier resolution (D-09, C-01/C-05) must map every tier to "no explicit model" or `auto` when `auto` is all that is listed. Per-agent `model` overrides (S-03) cannot work on Free.
7. **Fixed: events the port did not model.** The port gains `session.auto_mode_resolved` (`model`, `fallback`, `reason`), `session.usage_checkpoint` (`billedCredits`) and `session.shutdown` (`reason`, `billedCredits`, `error`). `session.usage_checkpoint` and `session.shutdown.billedCredits` set a floor under the session budget: when the runtime has billed more than the ledger holds (a call with no billed credits and no prices), the budget takes the difference, so warnings and engine-enforced limits never trail the runtime. The ledger itself is unchanged, because the gap has no model or agent. `session.auto_mode_resolved` reaches the runtime event log only. `session.model_change` landed in #64. What the spike found: `session.auto_mode_resolved`, `session.usage_checkpoint` (running `totalNanoAiu`) and `session.shutdown.accountingSnapshot`.

The spike's own permission handler returned `denied-interactively-by-user`. No tool was requested, so permissions were not exercised.

## Reproduce

```sh
PICA_LIVE=1 make verify UNIT=S-01   # runs both live checks (sends one prompt) and the A1 check
node spikes/s-01-runtime/s01.mjs models
node spikes/s-01-runtime/s01.mjs prompt
```

Both live checks need a Copilot CLI login (`copilot login`); without `PICA_LIVE=1` they are skipped. They never run in CI.
